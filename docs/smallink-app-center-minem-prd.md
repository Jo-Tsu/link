文档版本：1.1  
更新日期：2026-08-09  
产品阶段：目标设计，进入开发前评审  
产品名称：Smallink  
首个应用：MineM  
关联文档：[技术设计](./smallink-app-center-minem-technical-design.md)、[测试计划](./smallink-app-center-minem-test-plan.md)、[Smallink 主 PRD](./link-product-prd.md)、[个人记忆 PRD](./link-memory-prd.md)

## 0. 决策摘要

Smallink 新增“应用中心”，用于把具有独立领域能力的本地或外部产品集成进 Smallink。MineM 是第一个正式应用。

本需求不是新增一个普通连接器卡片，也不是在 Smallink 中重写一套 MineM。目标是：

1. Smallink 自动通过 MineM CLI 发现、启动并调用 MineM。
2. Smallink 内置一个不可因文件夹移动而失效的“MineM 素材库”默认项目。
3. 用户进入该项目后，既可以通过自然语言使用 MineM，也可以直接使用完整素材管理工作台。
4. Smallink 内的 MineM 工作台与 MineM 当前正式版本保持能力对齐，覆盖工作台、汇报、页面、案例、资源、故事线、导入任务、标签治理、版本、预览、编排和导出。
5. 对话、文件、CLI 调用、素材操作、搜索结果、读取快照、生成过程、版本关系和确认动作全部进入可追溯的数据链路。
6. AI 从这些事实中提炼候选记忆，用户确认后进入正式记忆，并在后续 MineM 任务中召回。
7. 应用中心、应用项目、应用智能体、应用界面、能力、数据和记忆均使用通用协议，后续接入其他产品时不需要复制 MineM 专用页面和状态机。

产品定位：

> Smallink 是个人 AI 工作系统；应用中心把外部优秀产品变成可对话、可执行、可沉淀、可记忆的 Smallink 应用。MineM 是首个应用，也是该框架的标准样板。

## 1. 背景与问题

### 1.1 当前事实

Smallink 已经具备 MineM 本机连接器，可以：

- 检查 MineM 状态；
- 搜索素材；
- 读取素材；
- 读取汇报页面；
- 查看版本；
- 查看来源关系。

MineM 当前 CLI 已经具备更完整的领域能力，包括页面构建、素材导入、案例导入、汇报创建、页面插入、替换、移动、移出和 HTML/PDF 导出。

### 1.2 当前问题

1. MineM 只以“连接器”出现，用户不知道可以把它当成长期工作空间。
2. 用户必须理解连接器、CLI、端口和工具开关，产品入口过于技术化。
3. MineM 会话没有一个稳定的系统项目作为归属，容易落入普通最近会话。
4. 当前能力主要只读，不能完成“提出目标到正式 MineM 产物”的闭环。
5. 搜索、读取和生成过程没有被统一组织为项目资料、产物和长期记忆。
6. 如果继续在代码中直接判断 `minem`，未来每接入一个产品都会增加一套分支、页面和数据逻辑。
7. 仅提供对话和少量素材卡片会迫使用户在 Smallink 与 MineM 两个客户端之间频繁切换，无法形成统一工作体验。

## 2. 产品目标与非目标

### 2.1 产品目标

1. 建立通用应用中心和应用运行协议。
2. MineM 安装或启用后自动创建系统默认项目。
3. 用户无需手动配置端口即可与 MineM 素材库对话。
4. MineM 未运行时由 Smallink 通过正式 CLI 自动启动。
5. 支持从素材搜索到页面/汇报生成、人工确认、正式发布和导出的完整流程。
6. 所有交互和执行事实可追溯、可去重、可恢复、可重新治理。
7. AI 能从 MineM 项目过程提炼有来源依据的候选记忆。
8. 后续应用能够复用同一套安装、项目、智能体、能力、权限、数据和记忆框架。
9. 用户无需离开 Smallink，即可完成 MineM 正式客户端现有的素材管理主流程。

### 2.2 非目标

1. 不复制、分叉或重新实现 MineM 的 React 业务界面；完整工作台通过 MineM 官方可嵌入界面模块和公开 API 复用同一套实现。
2. 不直接读取或写入 MineM SQLite 数据库。
3. 不把 MineM 全量二进制素材复制到 Smallink 数据库。
4. 不允许模型拼接任意 Shell 命令。
5. 不把所有界面操作机械转换成 CLI 子进程；CLI 服务于智能体和受控自动化，高频交互通过公开 UI/API 契约完成。
6. 不在首期建设应用商店交易、云端分发或第三方开发者结算。
7. 不把未经用户确认的 AI 推断直接写入正式记忆。

## 3. 基础术语

| 术语 | 产品含义 |
|---|---|
| 应用 | 在 Smallink 中拥有入口、项目、智能体、能力、数据和记忆策略的集成产品 |
| 应用中心 | 浏览、启用、配置、诊断和停用应用的统一入口 |
| 连接器 | 应用底层连接 CLI、API、MCP 或本地服务的技术适配器 |
| 应用实例 | 某台设备上某个应用的一次实际安装和连接状态 |
| 系统项目 | 由应用创建、没有普通文件夹依赖的长期工作空间 |
| 应用智能体 | 默认理解该应用领域对象、工具和工作流的专属智能体 |
| Capability | 应用对 Smallink 暴露的受控能力，例如搜索素材或创建汇报 |
| SensoryRecord | 从用户、文件、CLI 和工具运行进入系统的不可被 AI 覆盖的原始事实 |
| 素材引用 | Smallink 指向 MineM 素材 ID、编号和版本的稳定关系 |
| 候选记忆 | AI 根据多条事实提炼、等待用户确认的长期信息 |
| 应用工作台 | 外部应用在 Smallink 项目内提供的完整可交互业务界面 |
| 能力对齐 | Smallink 嵌入版与受支持 MineM 正式版本在核心素材管理能力上保持一致 |
| 语义操作事件 | 由工作台产生的搜索、预览、编排、合并、导出等业务事件，不是鼠标点击日志 |

## 4. 用户与核心场景

### 4.1 目标用户

- 使用 Smallink 完成日常工作的个人用户；
- 已安装或准备使用 MineM 的汇报创作者；
- 希望用自然语言复用历史页面和资料的用户；
- 需要保留来源、版本和修改原因的重度内容生产者。

### 4.2 核心场景

#### 场景 A：和素材库对话

用户进入“MineM 素材库”项目并输入：

> 找出以前做过的 AI 产品架构页面，优先选择适合老板阅读的版本。

Smallink 搜索 MineM，返回带缩略图、编号、来源汇报和版本的素材卡片。

#### 场景 B：根据项目资料创建汇报

用户上传文件或指定 Smallink 项目资料，要求生成汇报。Smallink 分析资料、检索 MineM 可复用页面、形成故事线、生成缺失页面、创建汇报并返回真实预览。

#### 场景 C：继续修改正式汇报

用户打开一份 MineM 汇报并输入：

> 把第三页改成老板只看结论和风险的版本。

Smallink 创建新页面版本并展示影响预览。用户确认后，MineM 替换正式汇报页槽，旧页面和旧版本不被删除。

#### 场景 D：沉淀个人方法

用户多次要求“首屏只保留结论、风险、责任和决策”。AI 合并多次事实，生成一条 `user_preference` 或 `reusable_pattern` 候选记忆，展示引用会话和 MineM 产物，用户确认后入库。

### 5.2 应用中心

首期应用中心只展示 MineM。其他未完成应用不显示占位卡片。

应用卡片显示：

- 名称、图标和一句话说明；
- 安装、运行、连接和兼容状态；
- 应用版本和协议版本；
- 默认项目入口；
- 最近使用时间；
- 主要操作。

卡片状态和操作：

| 状态 | 文案 | 主操作 |
|---|---|---|
| 未安装 | 未检测到 MineM | 查看安装说明 |
| 已安装未启用 | MineM 已安装 | 启用应用 |
| 启动中 | 正在启动 MineM | 查看进度 |
| 可用 | MineM 已连接 | 打开素材库 |
| 不兼容 | MineM 版本需要更新 | 打开 MineM |
| 服务异常 | MineM 暂时不可用 | 重新检查 |
| 已停用 | MineM 已停用 | 重新启用 |

### 5.3 应用详情

MineM 应用详情包含：

- 应用简介；
- 当前版本、CLI 版本、API 版本；
- 客户端和 CLI 路径；
- 运行健康状态；
- 可用能力和读写权限；
- 数据沉淀范围；
- 记忆提炼规则；
- 最近应用运行；
- 打开默认项目、重新检查和停用应用。

应用详情只负责安装、版本、能力、权限和诊断，不承载素材管理。完整素材管理位于 `system:minem` 项目的“素材工作台”中。

## 6. MineM 系统默认项目

### 6.1 创建规则

1. 启用 MineM 应用后创建唯一系统项目 `system:minem`。
2. 重复启用、升级或重装不能创建重复项目。
3. 系统项目不依赖 `/Users/...` 文件夹，不因源码目录移动而失效。
4. 系统项目可停用但不能作为普通项目永久删除。
5. 停用 MineM 时保留历史会话、资料引用、产物引用和记忆来源。

### 6.2 项目结构

MineM 系统项目不是一个只有对话记录的普通文件夹，而是包含两类工作面的完整应用空间：

```text
MineM 素材库
├── 对话
├── 工作台
├── 汇报
├── 页面
├── 案例
├── 资源
├── 故事线
├── 导入任务
└── 素材治理
```

“对话”负责自然语言目标、智能体执行、审批和结果解释；其余页面组成 MineM 素材工作台。用户从任一素材、汇报或故事线进入对话时，Smallink 必须携带稳定对象引用和当前版本。

### 6.3 项目首页

项目首页包含：

- MineM 连接状态；
- 新建专属对话；
- 最近 MineM 会话；
- 最近使用的素材；
- 最近生成的页面和汇报；
- 待确认发布动作；
- 待确认记忆候选；
- 快捷任务。
- 素材工作台各模块入口及真实数量；
- 正在导入、导出、分析或治理的任务。

快捷任务：

- 搜索素材；
- 查看最近汇报；
- 分析一份汇报；
- 查找可复用页面；
- 根据资料生成页面；
- 创建新汇报；
- 修改已有汇报；
- 导出 HTML/PDF。

### 6.4 会话归属

1. 从 MineM 项目创建的会话必须保存 `project_id=system:minem`。
2. 会话同时出现在 MineM 项目和最近会话中，但不能成为无归属会话。
3. 从素材或汇报卡片继续对话时，必须恢复原项目和素材上下文。
4. 普通项目可以临时启用 MineM 能力，但不会改变 `system:minem` 的唯一性。

## 7. 专属对话体验

### 7.1 自动连接

用户进入 MineM 项目或首次调用 MineM 能力时：

```text
发现 CLI
→ 检查 MineM 运行状态
→ 未运行则由正式 CLI 启动
→ 校验产品名和协议版本
→ 注册当前会话能力
→ 开始执行
```

用户不填写端口、Token、数据库路径或 Python 地址。

### 7.2 对话原则

1. 先搜索，再读取命中素材，不把全库塞入模型。
2. 先展示找到的素材，再说明为什么选择。
3. 写操作先形成计划和预览，再进入确认。
4. 所有完成结果必须返回真实素材编号、版本和可打开链接。
5. 失败必须显示失败步骤、是否产生部分结果和可恢复动作。
6. 对话中的素材和产物使用卡片，不以裸 JSON 或 URL 编码路径交付。

### 7.3 素材卡片

素材卡片至少显示：

- 名称；
- 类型；
- MineM 编号；
- 当前版本；
- 来源汇报或批次；
- 更新时间；
- 预览；
- 查看来源；
- 加入汇报；
- 基于此素材继续对话。

### 7.4 产物卡片

页面或汇报生成完成后显示：

- 名称和类型；
- MineM 编号；
- 状态和版本；
- 页面数量；
- 来源资料；
- 在 Smallink 预览；
- 在 MineM 打开；
- 继续修改；
- 导出 HTML/PDF；
- 查看运行与来源。

## 8. MineM 能力范围

### 8.0 完整素材工作台

Smallink 内的 MineM 工作台必须复用 MineM 的正式领域能力，并以当前受支持 MineM 版本为能力基线。首个完整版本至少包含：

| 模块 | 必备能力 |
|---|---|
| 工作台 | 素材统计、处理流水线、分类入口、最近素材和进行中任务 |
| 汇报 | 列表、搜索、筛选、分页、详情、预览、重命名、安全删除、故事线、演讲稿和导出 |
| 汇报编排 | 全页网格、拖拽排序、插入、多选、隐藏/恢复、移出、待生成页、确认应用和并发版本检查 |
| 页面 | 网格/列表、详情、预览、标签、来源、历史、版本、主版本、页面角色、临时组合预览和安全删除 |
| 案例 | 案例组列表、详情、页面组成、导入、更新和带引用检查的原子删除 |
| 资源 | 图片、Logo、图标、SVG、GIF、视频的分类、标签、预览、版本和导入 |
| 故事线 | 从汇报生成故事线、版本管理、来源汇报、查看结构和从故事线创建汇报 |
| 导入任务 | HTML、ZIP、图片、SVG、GIF、视频等导入，显示排队、运行、成功、失败、取消、重试和批次来源 |
| 素材治理 | 标签体系、手工标签、AI 标签任务、重复分析、语义/视觉合并、版本提升和来源谱系 |
| 预览与演示 | 16:9 预览、缩略图、整份汇报查看、演讲稿生成/导入/编辑/恢复以及本地朗读能力 |
| 导出 | 按已确认可见顺序导出离线 HTML ZIP 和 PDF，并显示进度、失败页和重试 |

能力对齐不是把 MineM 页面截图嵌入 Smallink。所有列表、筛选、详情、拖拽、弹窗、任务状态和错误都必须真实可交互，并使用 Smallink 的导航、语言、主题、加载和焦点规范。

### 8.0.1 对话与工作台互通

1. 素材工作台任何对象均可“继续对话”，并带入对象 ID、类型、版本和来源。
2. 对话生成的页面、汇报、故事线、导入任务和导出结果必须即时出现在对应工作台模块。
3. 智能体准备修改正式对象时，确认卡片可以打开工作台中的影响预览。
4. 工作台的筛选结果可以作为当前对话的受控素材集合，不把全库内容直接送入模型。
5. 对话和工作台共享任务状态、选择上下文和错误恢复，不建立两套运行记录。

### 8.1 P0 读取能力

| 能力 | 行为 | 默认权限 |
|---|---|---|
| 检查状态 | 检查版本、运行状态和素材统计 | 自动 |
| 搜索素材 | 搜索汇报、页面和资源 | 自动 |
| 读取素材 | 读取一项素材的受控内容 | 自动 |
| 读取汇报页面 | 查看汇报页槽和页面摘要 | 自动 |
| 读取版本 | 查看素材版本 | 自动 |
| 读取来源 | 查看素材来源和关系 | 自动 |

### 8.2 P1 创作能力

| 能力 | 行为 | 默认权限 |
|---|---|---|
| 构建页面草稿 | 根据结构化规范生成自包含 HTML | 自动 |
| 发布页面 | 把草稿正式纳入 MineM | 需确认 |
| 导入页面/汇报 | 导入用户指定的 HTML 或 ZIP | 需确认 |
| 创建汇报 | 使用已确认页面创建正式汇报 | 需确认 |
| 导出汇报 | 导出 HTML 或 PDF | 需确认目标位置 |

### 8.3 P2 编排能力

| 能力 | 行为 | 默认权限 |
|---|---|---|
| 插入页面 | 向正式汇报增加页面 | 需确认 |
| 替换页面 | 用新版本替换指定页槽 | 需确认 |
| 移动页面 | 调整正式汇报顺序 | 需确认 |
| 隐藏/移出页面 | 改变汇报编排但不删除源素材 | 需确认 |

智能体默认不能直接删除 MineM 源素材；用户可在素材工作台执行 MineM 已支持的安全删除流程，必须先展示引用影响并二次确认。

## 9. 数据资料沉淀

### 9.1 总原则

凡是通过 MineM 项目发生的输入、查询、读取、生成、修改、确认和导出，都必须留下可追溯记录。

“全部沉淀”不等于每次复制整个 MineM 素材库。Smallink 保存交互事实、读取快照、业务关系和稳定引用；MineM 保存正式素材文件、版本、编排和导出结果。

### 9.2 必须保存的事实

- 用户消息和附件；
- AI 输出；
- 应用、项目、会话、任务和运行标识；
- CLI 能力名、结构化参数摘要、开始和结束时间；
- CLI 原始机器返回的受控快照；
- 搜索查询、命中编号和排序；
- 实际读取过的素材内容快照、版本和内容哈希；
- 草稿文件和预览；
- 用户确认、拒绝和编辑动作；
- 正式 MineM 素材 ID、编号、版本和链接；
- 导出任务和最终文件引用；
- 错误、重试、取消和恢复记录。
- 工作台产生的搜索、筛选、查看、选择、标签、版本、编排、合并、删除、导入和导出语义事件；
- 工作台打开对象时的稳定引用和必要版本快照。

### 9.3 去重与版本

1. 素材按 `app_instance + asset_id + version_id` 唯一识别。
2. 相同内容按内容哈希去重。
3. 重复搜索保留查询事件，但不重复保存相同素材正文。
4. 素材版本变化后保存新快照并保留旧快照引用。
5. CLI 重试保留运行事件，但必须使用幂等键防止重复发布。
6. 所有关系都能回到原会话、原工具运行和原 MineM 版本。

## 10. 记忆提炼

### 10.1 记忆候选来源

AI 可以从以下事实组合提炼候选记忆：

- 用户重复表达的视觉和结构偏好；
- 用户接受、拒绝或修改页面的动作；
- 汇报目标、受众和场景；
- 重要产品决策和修改原因；
- 可复用的故事线、页面方法和检查规则；
- 最终产物摘要；
- 文档洞察和未解决问题。

### 10.2 支持的记忆类型

| 类型 | MineM 场景示例 |
|---|---|
| `user_preference` | 老板汇报首屏偏好结论、风险、责任和决策 |
| `project_context` | 某份汇报的目标、受众和背景 |
| `product_decision` | 最终选择哪一种页面结构及原因 |
| `reasoning_process` | 用户如何判断素材价值和表达顺序 |
| `open_question` | 尚未补齐的数据或待确认问题 |
| `reusable_pattern` | 可复用的故事线和页面设计方法 |
| `work_habit` | 用户通常先审结构再审视觉 |
| `artifact_summary` | 页面或汇报的最终摘要 |
| `document_insight` | 从 MineM 素材中发现的重要洞察 |

### 10.3 人工确认

1. 原始事实不会自动成为正式记忆。
2. AI 应跨消息、工具调用和产物合并后生成候选，不逐条机械总结。
3. 候选必须显示内容、类型、价值解释、来源和引用 MineM 素材。
4. 用户可以接受、编辑、合并或忽略。
5. 接受后写入正式记忆，并保留来源快照和提炼版本。
6. 后续 MineM 对话只召回与当前目标相关的已确认记忆。

## 11. 权限与人在回路

### 11.1 权限等级

- 读取：连接后默认允许。
- 生成本地草稿：默认允许，记录产物。
- 写入 MineM：必须确认。
- 修改正式汇报编排：必须确认并显示影响对象。
- 导出文件：必须确认格式和目标位置。
- 删除源素材：首期禁止通过智能体执行。

### 11.2 确认卡片

确认前必须显示：

- 将执行的动作；
- 影响的汇报、页面和版本；
- 新增、替换或移动的页槽；
- 是否保留旧版本；
- 可预览结果；
- 失败后的回滚或恢复方式。

## 12. 运行状态与失败恢复

### 12.1 状态

```text
准备中 → 搜索资料 → 读取素材 → 生成草稿 → 等待确认
→ MineM 执行中 → 验证结果 → 已完成
```

异常状态：

- MineM 未安装；
- MineM 启动超时；
- CLI 版本不兼容；
- 素材不存在或版本变化；
- 用户取消；
- 等待确认；
- CLI 执行失败；
- 已产生部分结果；
- 导出失败但正式汇报已创建。

### 12.2 恢复要求

1. 重启 Smallink 后能恢复任务和等待确认状态。
2. MineM 重启后能通过素材编号重新定位结果。
3. 网络或进程失败不得重复创建正式素材。
4. 部分成功必须显示已创建对象和未完成步骤。
5. 用户可以从失败步骤重试，不必重新运行整个对话。

## 13. 非功能需求

### 13.1 性能

- 打开应用中心时不自动启动 MineM。
- 打开 MineM 项目后 500 ms 内显示本地项目骨架和缓存状态。
- MineM 启动和连接过程必须异步，并显示明确进度。
- 普通搜索首个可见结果目标小于 3 秒。
- 长任务持续显示阶段、已用素材和产物状态。
- 大型 CLI 返回必须裁剪后进入模型，原始快照按数据策略保存。
- 工作台列表、筛选、翻页、预览和拖拽不能逐次启动 CLI 进程。
- 首屏先恢复本地壳、导航和缓存摘要，MineM 工作台异步连接；加载中不得出现可点击但无响应的假界面。
- 1,000 条素材使用服务端分页或虚拟化，切换模块不重新拉取不相关的全量数据。

### 13.2 稳定性

- CLI 超时、异常退出和无效 JSON 都有明确错误。
- Smallink 关闭或崩溃后不得遗留失控写任务。
- 相同幂等请求不能创建重复页面或汇报。
- MineM 不可用不能阻塞 Smallink 其他项目启动。

### 13.3 隐私

- 所有数据默认留在本机。
- 不把 MineM 数据发送到非当前模型 Provider。
- 模型输入只包含当前任务需要的素材片段。
- 日志和记忆来源中不保存 Token 等秘密字段。

## 14. 产品指标

- 自动启动成功率和平均耗时；
- MineM 项目会话归属正确率；
- 搜索结果打开率；
- 草稿到正式发布转化率；
- 正式操作重复创建率；
- 任务失败恢复成功率；
- 候选记忆接受、编辑、合并和忽略比例；
- 被召回记忆对后续任务的采用率；
- 产物来源链完整率。

## 16. 验收标准

1. MineM 是应用中心第一个真实应用，不显示未实现应用。
2. 启用 MineM 后只创建一个系统默认项目。
3. 用户进入默认项目即可对话，不需要配置端口。
4. MineM 未运行时能由 CLI 自动启动，失败时有可理解提示。
5. 所有 MineM 会话归属默认项目。
6. 搜索和读取结果显示真实编号、版本和来源。
7. 页面或汇报写入前经过人工确认。
8. 完成后显示可打开、可继续修改、可导出的产物卡片。
9. 重启后会话、运行、资料引用、产物和待确认状态可恢复。
10. 相同命令重试不会重复创建正式素材。
11. 原始事实、CLI 运行和 MineM 版本可以互相追溯。
12. AI 能跨多条事实生成候选记忆，并显示为什么提炼和引用来源。
13. 未确认候选不会进入正式记忆和后续召回。
14. 停用 MineM 后历史数据仍可查看，但新调用被阻止。
15. MineM 不可用不影响 Smallink 其他项目和导航。
16. 用户无需离开 Smallink 即可完成汇报、页面、案例、资源、故事线、导入、版本、治理、预览和导出的核心管理流程。
17. 工作台对象与 MineM 客户端使用同一 ID、版本和领域状态，不产生第二份事实数据。
18. 对话产物会出现在工作台，工作台对象可携带上下文继续对话。
19. 高频界面操作不启动 CLI 子进程，列表和预览没有明显主线程卡顿。
20. MineM 升级导致界面或 API 契约不兼容时，Smallink 显示明确升级提示并阻止危险写操作。
