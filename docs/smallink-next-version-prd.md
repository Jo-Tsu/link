## 0. 文档定位

本文基于当前仓库中的真实前端入口、后端 API、持久化对象和测试行为，定义 Smallink 下一版本需要交付的产品收敛范围。

本文不是重新描述远期平台架构，也不把尚未实现的 Postgres、向量检索、知识库或多人协作写成当前能力。若本文与旧文档中的“当前状态”冲突，以当前代码和本文的基线判断为准；远期目标仍以产品总 PRD 为准。

本文解决四个问题：

1. Smallink 当前究竟是什么产品。
2. 用户现在能够完成哪些真实闭环。
3. 哪些能力虽然已有代码，但尚未形成清晰、可信的产品体验。
4. 下一版本应优先补齐什么，而不是继续横向增加入口。

优先级定义：

| 优先级 | 含义 |
|---|---|
| P0 | 本版本必须完成，缺失即不能认为产品主线成立 |
| P1 | 本版本尽量完成，可在不破坏 P0 闭环的情况下后置 |
| P2 | 后续版本方向，本版本只保留兼容边界 |

## 1. 产品结论

### 1.1 一句话定义

> Smallink 是一个运行在个人电脑上的个人 AI 工作系统：用户通过会话或自动化提出目标，智能体调用模型、文件、终端、Skill、MCP 和连接器完成真实工作；运行事实被保留，经 AI 提炼和用户确认后形成可复用的长期记忆。

### 1.2 当前产品不是

Smallink 不是：

- 只负责问答的聊天客户端；
- 需要用户手工维护大量条目的“第二大脑”；
- 只展示智能体概念、但无法交付文件和结果的演示产品；
- 默认把全部本地数据上传到云端的 SaaS；
- 以连接器数量作为核心价值的集成市场；
- 已完成知识库、多人协作和云端同步的平台。

### 1.3 下一版本的核心任务

下一版本不以“增加更多功能”为主目标，而以“把已有能力收敛成一条可信主线”为目标：

```text
项目或会话
→ 提出目标
→ 看到 Smallink 正在工作
→ 必要时批准或回答
→ 获得回复与产物
→ 可查看运行过程
→ 真实事实进入数据池
→ AI 自动生成候选记忆
→ 用户确认后在未来任务中生效
```

## 2. 当前真实产品基线

### 2.1 已形成真实链路

| 能力 | 当前判断 | 真实边界 |
|---|---|---|
| 桌面客户端 | 已可用 | Tauri + React，连接本地 FastAPI Sidecar |
| 会话工作台 | 已可用 | 支持流式输出、附件、工具、审批、重试、中断和产物预览 |
| 模型接入 | 已可用 | 支持多 Provider、模型选择和独立的记忆模型用途 |
| 任务运行记录 | 已可用第一版 | 会话对应持久 Task，每次执行对应 TaskRun，可记录根和子 AgentRun |
| 项目 | 已可用骨架 | 有 Project 实体、创建入口、会话归组和项目徽章；管理体验未完成 |
| 运行中心 | 已可用第一版 | 可查看 Task、TaskRun、AgentRun 和事件 |
| 多智能体 | 已可用纵向切片 | Explorer 可形成真实子运行；尚非通用多智能体调度系统 |
| 审批与 Inbox | 已可用 | 支持行内处理、无人值守转 Inbox、恢复执行和幂等处理 |
| 自动化 | 部分可用 | 支持定时任务、立即运行、独立运行会话和历史记录 |
| 连接器 | 已可用有限集合 | 客户端正式展示 MineM、Codex、TRAE CLI 三个已验证本地来源 |
| 原始事实池 | 已可用第一版 | 运行和连接器数据进入 `sensory_records`，可搜索、筛选、查看和删除 |
| 记忆治理 | 已可用第一版 | 可生成候选，接受、编辑后接受、合并或忽略 |
| 正式记忆 | 已可用第一版 | 只有确认后的 active 记忆会按范围和相关性注入未来任务 |
| Skill / MCP | 已可用 | 可发现、导入和调用真实能力 |
| 知识库 | 未形成产品能力 | 当前没有正式知识条目、索引和引用闭环 |

### 2.2 当前核心对象关系

下一版本统一采用以下用户可解释模型：

```text
Project（可选）
└── Conversation / Session
    └── Task（当前版本一条会话对应一个长期目标容器）
        ├── TaskRun 1
        │   └── Root AgentRun
        │       └── Child AgentRun 0..N
        ├── TaskRun 2
        └── Artifact 0..N

Automation
└── Automation Run
    └── 独立 Conversation / Task / TaskRun

SensoryRecord
└── MemoryCandidate
    └── FormalMemory（用户确认后）
```

本版本明确：

- 会话是用户交互和上下文容器。
- Task 是该会话当前承载的长期工作目标。
- 每次发送、重试、恢复或自动化触发形成一次新的 TaskRun 或恢复既有等待中的 TaskRun。
- 一个 TaskRun 至少有一个根 AgentRun，可以有多个子 AgentRun。
- 用户在当前版本提出完全独立的新目标时，应新建会话；“单会话多独立 Task”不在本版本扩展范围内。
- 项目是组织范围，不复制会话、记忆、产物或文件。

### 2.3 当前主要产品断点

#### A. 能力丰富，但用户主线不够聚焦

会话、Agents、Runs、Automations、Inbox、Connectors、Memory、Activity 都有入口，但用户不容易快速理解：

- 我现在在做什么；
- Smallink 是否仍在运行；
- 当前结果属于哪个项目；
- Runs 和 Agents 的区别；
- 数据已经导入是否等于已经学会；
- 哪些记忆已经真正生效。

#### B. 项目只有骨架，没有完整管理闭环

当前已能创建 Project 并按项目展示会话，但仍缺少：

- 重命名、图标、说明、状态和默认配置的前端管理入口；
- 归档项目的查看和恢复入口；
- 删除项目的影响说明；
- 项目默认智能体和默认模型在新会话中的稳定继承；
- 创建失败、目录重复等明确反馈。

#### C. 记忆闭环可用，但仍偏“数据库管理”

当前用户需要主动点击“生成候选”，再进入候选列表处理。该流程证明了治理链路，但不符合“Smallink 越用越懂我”的价值预期。

下一版本需要同时满足：

- AI 自动整理，减少用户主动维护成本；
- AI 生成的记忆必须确认后才生效；
- 记忆在对话中自然体现，而不是不断暴露内部编号和存储术语；
- 用户能看懂 Smallink 当前如何理解自己。

#### D. 文档状态已落后于实现

部分旧文档仍把项目、原始事实和正式记忆标记为“待建设”，项目模块清单也仍显示未完成。下一版本必须建立“目标设计”和“当前事实”分离的文档治理规则。

## 3. 产品目标与非目标

### 3.1 P0 产品目标

1. 用户首次启动后，可以在五分钟内连接模型并开始第一项真实工作。
2. 用户发送目标后，界面立即显示明确运行状态，不出现无反馈空白期。
3. 项目从“会话分组”升级为可创建、配置、归档和安全删除的一等组织对象。
4. 会话、Task、TaskRun、AgentRun 在工作台和运行中心使用一致的状态事实。
5. 审批、问题和异常能在原会话或 Inbox 中处理，并恢复原执行。
6. 本地来源完成“授权 → 导入 → 查看原始数据 → 自动生成候选 → 人工确认 → 未来生效”闭环。
7. 记忆体验从“手工整理数据库”转向“Smallink 正在逐步了解我”。
8. 产品只展示真实可用能力，不展示未接通的连接器和功能占位。

### 3.2 P1 产品目标

1. 项目能够聚合会话、运行、自动化、来源数据、记忆和产物的摘要。
2. 记忆支持批量确认、冲突提示和归档恢复。
3. Runs 与 Agents 的信息层级进一步收敛，减少重复入口。
4. `chat` 和 `title` 模型用途配置真正接入运行链路。
5. 自动化支持更清晰的失败重试和恢复说明。

### 3.3 本版本非目标

- 多人协作、团队权限和企业工作区；
- 云端强制同步或远程 Worker；
- 完整知识库和语义文档检索；
- Postgres + pgvector 正式迁移；
- 通用 DAG 多智能体编排、跨任务依赖和预算系统；
- 事件型自动化的完整连接器生态；
- Persona 市场正式发布；
- 在未完成交互打磨前重新开放 Plan 和 Custom 权限模式；
- 为增加数量而开放未经端到端验证的连接器。

## 4. 核心用户与使用场景

### 4.1 核心用户

Smallink 下一版本优先服务单个专业用户：

- 需要 AI 直接处理本地文件、代码、报告或资料；
- 同时使用多个 AI 编程或工作工具，希望保留跨会话经验；
- 关注隐私、来源、权限和可恢复性；
- 不愿频繁手工整理“记忆库”；
- 有重复性工作，希望逐步交给自动化。

### 4.2 核心任务

| 场景 | 用户动作 | 产品结果 |
|---|---|---|
| 快速完成一次工作 | 输入目标并附加文件 | 展示运行状态，调用工具，交付回复和产物 |
| 持续推进项目 | 创建项目并在项目内新建会话 | 自动继承目录和默认配置，所有会话按项目组织 |
| 查看执行细节 | 打开 Runs 或协作详情 | 查看每次运行、子智能体、事件、错误和结果 |
| 处理阻塞决定 | 在会话或 Inbox 批准、拒绝或回答 | 原执行幂等恢复，不重复调用工具 |
| 导入既有 AI 工作历史 | 连接 Codex 或 TRAE CLI | 增量导入原始事实，可查看同步结果和来源 |
| 让 Smallink 逐渐了解自己 | 正常使用并处理候选记忆 | 确认后的偏好和项目上下文在后续任务中生效 |
| 定期执行工作 | 创建自动化或立即运行 | 使用同一任务、权限、运行和产物机制执行 |

## 5. 产品原则

### 5.1 工作优先

默认首页必须让用户直接开始工作。产品价值首先来自完成目标，而不是配置、浏览模块或管理数据。

### 5.2 本地优先，但不伪装“完全离线”

本地状态、文件和治理数据默认保存在用户电脑上；调用外部模型时，必须明确说明选中的上下文会发送给相应 Provider。

### 5.3 状态必须来自后端事实

工作台、Runs、Agents、Automation、Inbox 和侧边栏角标不得分别推断状态。相同业务对象在不同页面必须显示相同结果。

### 5.4 AI 提炼，用户控制

AI 可以自动生成候选、摘要和建议，但不得绕过确认直接写入正式记忆，也不得未经审批执行高风险动作。

### 5.5 原始事实先于 AI 结论

导入、消息、工具、文件和运行事件先作为可追溯事实保存。候选记忆和正式记忆必须保留来源。

### 5.6 渐进披露

普通用户只需要看到目标、进度、决定和结果；模型、事件、AgentRun、提示词和来源证据应在需要时展开。

### 5.7 不展示假能力

未接通、未授权或仅有后端草稿的功能不得以可用入口出现在正式界面。

## 6. 信息架构

### 6.1 一级区域

| 区域 | 核心问题 | 本版本定位 |
|---|---|---|
| 工作台 | “我要做什么” | 默认首页，会话、输入、运行、审批和产物 |
| 项目 | “这些工作属于哪里” | 位于侧边栏，组织项目和项目会话 |
| Runs | “系统实际执行了什么” | 运行事实中心 |
| Automations | “哪些工作会自动执行” | 自动化定义与运行历史 |
| Inbox | “现在有哪些事需要我决定” | 阻塞性审批、问题和通知 |
| Connectors | “Smallink 可以读取哪些外部来源” | 授权、同步、状态和来源入口 |
| Memory | “Smallink 长期理解了我什么” | 用户画像、候选确认、正式记忆、来源和提示词 |
| Settings | “Smallink 如何运行” | 模型、文件、语音、外观和安全设置 |

### 6.2 次级区域

- Agents：解释智能体成员和展示真实协作运行；不得与 Runs 形成两套状态中心。
- Activity / Audit：面向诊断和安全审计，放在次级菜单。
- Skills / MCP：作为能力管理放在 Connectors 页面内，不继续扩张一级导航。
- System Prompts：继续保留在 Memory 内，满足用户理解“Smallink 为什么这样回答”的透明度需求。

### 6.3 首页与返回规则

- 点击品牌标识始终回到工作台。
- 从 Runs、Automations、Inbox 打开具体会话后，必须提供返回来源页面的路径。
- 页面已经加载过时，切换不得再次显示明显的整页冷启动闪烁。
- 项目会话、自动化运行会话和普通会话必须有清晰来源标识。

## 7. 功能需求

### 7.1 首次启动与激活

#### FR-ONB-01 模型连接（P0）

用户首次启动时先选择并验证模型 Provider。

要求：

- 显示 Provider、数据发送说明和密钥本地保存说明。
- 验证成功后才能将模型标记为可用。
- 允许跳过，但进入工作台后必须持续显示“尚未连接模型”的可操作状态。
- 不得用前端硬编码模型列表伪装后端已支持。

验收：

- 已连接模型的用户完成引导后可立即发送消息。
- 未连接模型的用户点击发送时进入模型连接流程，而不是静默失败。
- 冷启动加载模型列表期间显示明确加载状态。

#### FR-ONB-02 本地来源说明（P0）

引导第二步只展示当前构建中真实可用的来源。

要求：

- 正式展示 MineM、Codex 和 TRAE CLI。
- 明确“不会自动连接，必须由用户授权目录或本地应用”。
- 引导阶段不要求连接来源，不阻塞首次工作。
- 完成页提供“开始工作”和“创建第一个自动化”两个真实入口。

---

### 7.2 工作台与会话

#### FR-WORK-01 开始一项工作（P0）

用户可以在普通会话或项目会话中输入目标、粘贴或拖入文件并发送。

要求：

- 发送后 100ms 内进入可见的 `running` 状态。
- 第一段模型文本返回前显示“正在输出”或等价的动态状态。
- 模型推理、工具调用、审批和最终回复在一个连续时间线中呈现。
- 不得因尚无流式文本而回到空白欢迎页。
- 运行中可以中断；中断不删除已保存事件和产物。

#### FR-WORK-02 会话与运行语义（P0）

本版本采用“一条会话对应一个 Task 容器”的稳定模型。

要求：

- 会话首个有效目标创建 Task。
- 每次正常发送、重试或自动化触发形成 TaskRun。
- 等待审批后的继续应恢复原 TaskRun，不创建重复执行。
- 完全独立的新目标通过新建会话承载。
- Runs 页面可以从 Task 进入每次 TaskRun，再进入 AgentRun 和事件。

#### FR-WORK-03 连接恢复与幂等（P0）

要求：

- WebSocket 断线后自动重连并恢复已保存消息。
- 相同 `client_message_id` 不得重复执行工具。
- 应用重启后，等待审批的运行仍可恢复。
- 无法恢复的运行必须显示 `cancelled`、`failed` 或 `interrupted`，不能永久停在 `running`。

#### FR-WORK-04 产物（P0）

要求：

- 会话侧栏持续展示该会话产生的文件。
- 支持预览文本、代码、HTML、图片、PDF、CSV 和表格类产物。
- 支持复制路径、默认应用打开和 Finder 中显示。
- 产物入口在侧栏收起时仍可发现。
- 自动化运行产生的产物必须归属对应运行会话。

#### FR-WORK-05 权限模式（P0）

正式展示三种模式：

| 模式 | 行为 |
|---|---|
| Discuss | 讨论和读取，不执行编辑与命令 |
| Ask for approval | 编辑、命令和高风险操作前请求确认 |
| Full access | 在清楚提示风险后按已授予范围执行 |

要求：

- 运行中切换模型或权限模式时，前端不得显示后端未接受的状态。
- Full access 首次启用必须明确影响范围。
- Plan 和 Custom 在交互未完成前继续隐藏。

---

### 7.3 项目

#### FR-PROJ-01 创建项目（P0）

要求：

- 从侧边栏 Projects 标题的 `+` 创建项目。
- 使用原生目录选择器获取绝对路径和系统授权。
- 名称默认取目录名，用户可在创建前修改。
- 相同目录已存在项目时，不创建重复记录；应提示并定位到已有项目。
- 创建失败必须显示原因，不得静默关闭弹窗。

#### FR-PROJ-02 既有会话归组（P0）

要求：

- 创建项目后，将相同规范化 workspace 且尚未归属项目的既有会话自动关联。
- 迁移不得修改或复制原会话内容。
- 无项目会话继续显示在 Recent。

#### FR-PROJ-03 项目内新建会话（P0）

要求：

- 新会话继承 `workspace_path`、`project_id`、`default_agent` 和 `default_model`。
- 已确定目录时跳过 FolderGate。
- Composer 明确显示项目名称和图标。
- 项目上下文不得意外继承其他 Persona 的 scratch 目录。

#### FR-PROJ-04 项目管理（P0）

项目行提供管理入口，至少支持：

- 重命名；
- 修改图标；
- 编辑说明；
- 配置默认智能体和默认模型；
- 状态切换：`active`、`paused`、`completed`、`archived`；
- 删除项目。

删除规则：

- 删除 Project 记录和关联关系；
- 不删除会话；
- 不删除本地目录和文件；
- 不删除原始数据、记忆和产物；
- 确认框必须说明具体影响。

归档规则：

- 归档项目不出现在默认 Projects 列表；
- 可从“已归档项目”查看并恢复；
- 归档项目的历史会话仍可搜索和打开。

#### FR-PROJ-05 项目摘要（P1）

增加项目详情或摘要面板，展示：

- 项目说明和状态；
- 最近会话；
- 最近运行及失败数；
- 自动化；
- 已确认项目记忆；
- 来源记录数量；
- 最近产物。

该页面只聚合引用，不复制业务数据。

### 7.4 Runs 与多智能体

#### FR-RUN-01 统一运行事实（P0）

Runs 是运行状态的唯一事实页面。

要求：

- 列表显示 Task 标题、项目、状态和最近更新时间。
- 详情显示每次 TaskRun 的触发方式、模型、模式、开始与结束时间和错误。
- AgentRun 以父子树展示角色、状态、输入、输出、模型和事件。
- 从 Run 可以打开对应会话。
- 工作台、Runs 和 Agents 对同一运行显示一致状态。

#### FR-RUN-02 Agents 页面边界（P0）

Agents 页面用于：

- 解释 Smallink 的智能体结构；
- 展示已发生的协作运行；
- 查看子智能体结果。

Agents 页面不得：

- 创建第二套任务状态；
- 展示没有真实运行记录的“正在协作”；
- 让用户误以为所有内置角色都已开放为可配置产品。

#### FR-RUN-03 运行恢复（P1）

要求：

- 区分可恢复等待、重启中断、用户取消和执行失败。
- 对可重试失败提供重试入口，并明确将创建新的 TaskRun。
- 对重启中断说明已保留的消息、事件和产物。

### 7.5 审批与 Inbox

#### FR-INBOX-01 行内处理（P0）

用户正在查看会话时，计划、目录授权、工具审批和问题应优先在 Composer 上方处理。

要求：

- 批准、拒绝或回答后立即更新卡片状态。
- 原执行只恢复一次。
- 拒绝后智能体可以解释影响并继续生成可行结果。

#### FR-INBOX-02 无人值守处理（P0）

用户开启“Send approvals to Inbox”后：

- 审批和问题进入统一 Inbox；
- 会话显示等待状态；
- 用户可以在 Inbox 或原会话处理同一事项；
- 首个有效响应生效，后续响应显示已处理；
- 处理后恢复原 TaskRun。

#### FR-INBOX-03 Inbox 范围（P0）

Inbox 只承载需要用户及时处理的阻塞事项：

- 工具审批；
- 问题；
- 目录授权；
- 自动化异常通知。

普通候选记忆不进入阻塞性 Inbox，避免形成高频确认压力；Memory 页面通过低打扰角标提示待确认数量。

### 7.6 Connectors 与原始数据

#### FR-CONN-01 真实目录（P0）

要求：

- 正式页面只展示当前构建已验证的连接器。
- 隐藏连接器不得删除既有凭据或数据。
- 每个连接器显示用途、授权范围、连接状态、最后同步状态和断开入口。

#### FR-CONN-02 一键授权与导入（P0）

Codex 和 TRAE CLI 使用统一流程：

```text
选择本地目录
→ 授权
→ 连接
→ 探测
→ 增量导入
→ 显示结果
→ 查看源数据
```

要求：

- 不要求用户手工执行多条命令完成连接。
- 连接成功但导入失败时保留真实“已连接”状态，并提供重试。
- 重复同步保持幂等，只报告新增记录。
- 超大、损坏或未完成文件不能阻塞完整同步。

#### FR-DATA-01 数据状态表达（P0）

产品必须明确区分：

```text
已连接
≠ 已同步
≠ 已生成候选
≠ 已确认记忆
≠ 已在任务中使用
```

每个阶段显示数量、最近时间和下一步入口。

#### FR-DATA-02 原始数据浏览（P0）

要求：

- 支持来源、治理状态、关键词、项目和会话筛选；
- 支持分页和查看原文；
- 显示来源位置、导入时间和敏感级别；
- 删除前说明是否已被候选或正式记忆引用；
- P0 保持单条删除，批量影响预览列入 P1。

### 7.7 记忆

#### FR-MEM-01 自动形成候选（P0）

候选生成从“用户手动启动的主要动作”改为“后台自动运行的默认行为”。

触发时机：

- 本地来源成功导入后；
- 会话完成并进入空闲后；
- 失败记录被用户主动重试时。

要求：

- 后台任务不阻塞当前会话和页面操作；
- 失败可重试，并保留真实状态；
- 对相同原始记录保持幂等；
- 敏感内容按现有策略跳过或脱敏后再发送给记忆模型；
- 保留“手动生成/重试”作为诊断和兜底入口，而不是正常使用前提。

#### FR-MEM-02 确认后生效（P0）

所有 AI 生成记忆必须经过用户决定：

- Accept：按原内容确认；
- Edit and accept：编辑后确认；
- Merge：合并到既有正式记忆；
- Ignore：忽略并记录决定。

只有 `active` 正式记忆可注入未来任务。Pending、ignored、archived 或失败记录不得进入上下文。

#### FR-MEM-03 Memory as Personality（P0）

Memory 首页从“存储管理面板”升级为“Smallink 对我的理解”。

首页优先展示：

- 用户偏好；
- 沟通方式；
- 决策习惯；
- 长期目标；
- 项目上下文；
- 待确认的新理解；
- 最近发生变化的理解。

交互原则：

- 使用自然语言摘要，不以数据库 ID 作为主要信息；
- 每条理解仍可展开查看来源、范围、版本和模型；
- 用户可以通过正常对话纠正 Smallink，纠正内容进入高优先级候选；
- 不要求用户为了获得价值而手工创建大量分类或标签；
- 正式记忆在回答中自然生效，不强制展示类似 `[Memory #12]` 的内部引用。

#### FR-MEM-04 范围和检索（P0）

本版本继续使用已验证的范围：

- global：所有任务可用；
- workspace：只在对应项目目录可用；
- session：只在特定会话可用。

要求：

- 按最新用户消息进行相关性排序；
- 在上下文预算内注入；
- 记录实际使用的 memory_id 和 version_id；
- 记忆不会写回会话历史；
- 项目记忆不得泄漏到其他 workspace。

#### FR-MEM-05 冲突与批量治理（P1）

要求：

- 发现同一偏好或事实的新旧冲突；
- 用户可以替换、保留两者或限定作用域；
- 支持候选批量接受和忽略；
- 支持正式记忆归档与恢复。

#### FR-MEM-06 提示词透明度（P0）

Memory 内保留 System Prompts 入口。

要求：

- 展示 Agent Persona、Narration、Environment、`AGENTS.md`、Memory Guidance、Skill Catalog 和每轮临时上下文的结构；
- 区分可编辑、谨慎修改和系统动态生成层；
- 动态内容明确标记为预览，不伪装成固定文本；
- 修改能力未开放时保持只读，不提供无效保存按钮。

## 8. 状态模型

### 8.1 Task / TaskRun / AgentRun

| 状态 | 用户含义 | 允许操作 |
|---|---|---|
| pending | 已创建，尚未开始 | 等待 |
| running | 正在执行 | 查看、中断 |
| waiting_approval | 等待用户决定 | 批准、拒绝、回答 |
| completed | 已完成 | 查看、继续会话、重试 |
| failed | 执行失败 | 查看错误、重试 |
| cancelled | 用户取消或重启中断 | 查看已保存结果、重新运行 |

不同页面不得使用 `idle`、`ok`、`done` 等同义值制造不同业务状态；展示层可翻译，但后端状态需要统一映射。

### 8.2 Project

| 状态 | 行为 |
|---|---|
| active | 默认显示并参与新会话上下文 |
| paused | 保留历史，不作为推荐的新工作入口 |
| completed | 只读展示为已完成项目，可继续打开历史 |
| archived | 默认隐藏，可搜索、查看和恢复 |

### 8.3 Memory

| 状态 | 是否可注入 | 用户动作 |
|---|---|---|
| pending | 否 | 接受、编辑、合并、忽略 |
| active | 是 | 查看、后续 P1 归档 |
| ignored | 否 | 查看决定记录 |
| archived | 否 | P1 恢复 |
| failed | 否 | 重试治理 |

### 8.4 Connector / Sync

连接状态和同步状态必须分离：

| 维度 | 状态示例 |
|---|---|
| 连接 | disconnected / authorizing / connected / error |
| 同步 | never / probing / syncing / success / partial / failed |

“connected + failed”是合法状态，表示授权仍有效但最近一次导入失败。

## 9. 异常与空状态

所有正式页面必须覆盖：

- 初次无数据；
- 加载中；
- 加载失败；
- 数据为空；
- 部分成功；
- 后端不可用；
- 状态可能过期；
- 操作失败；
- 可重试；
- 对象已被其他页面处理或删除。

关键规则：

1. 服务未就绪时显示本地服务恢复状态，不无限展示通用 Loading。
2. 创建项目、连接来源、生成候选和运行自动化失败时保留用户输入。
3. 后台仍在运行时，页面切换和重连不得把状态重置为“未开始”。
4. 对象已删除时返回列表和明确提示，不永久停留在详情 Loading。
5. 部分成功必须分别展示成功项和失败项。

## 10. 隐私、安全与信任

### 10.1 数据边界

- 本地会话、运行、来源和记忆默认保存在本机状态目录。
- 只有执行模型请求所需的提示词和选中上下文发送给配置的 Provider。
- 连接本地来源必须由用户通过目录选择或明确授权完成。
- 断开连接器不自动删除已导入事实；删除数据是独立动作。

### 10.2 高风险动作

- 文件写入、命令执行、外部发送和不可逆操作进入统一 Policy。
- Approval 必须展示工具名、关键参数和影响范围。
- “始终允许”授权必须限定工作区、工具或目标，不得无限扩大。
- Full access 不等于绕过操作系统权限和连接器授权。

### 10.3 记忆安全

- AI 不能直接创建 active 正式记忆。
- 候选必须有来源。
- 正式记忆修改保留版本和决定记录。
- 删除原始来源前，应提示对候选或正式记忆的影响。
- 敏感原始记录不得未经策略处理发送给外部模型。

## 11. 非功能需求

### 11.1 响应与性能

- 用户发送后 100ms 内出现本地运行反馈。
- 页面切换 300ms 内出现目标页面结构或明确加载状态。
- 普通列表 1 秒内出现数据、空状态或错误。
- 流式增量不得因同步 SQLite 写入导致明显卡顿。
- 大文件解析、来源同步和记忆治理不得阻塞 UI 主线程或 FastAPI 事件循环。
- 长列表使用分页、增量加载或虚拟化。

### 11.2 稳定性

- REST 和 WebSocket 都受启动令牌保护。
- 消息发送、Inbox 决定、同步和创建操作必须幂等。
- SQLite 继续使用 WAL、busy timeout 和一致的连接配置。
- 客户端关闭或系统睡眠后，重连不得重复执行工具。
- 数据迁移失败时停止危险写入并显示可诊断错误。

### 11.3 可访问性与国际化

- 核心操作支持键盘。
- 焦点状态清晰可见。
- 状态不能只依赖颜色。
- 中英文文案使用统一翻译层。
- 对话框支持 Escape、焦点约束和明确的确认/取消顺序。

### 11.4 测试要求

P0 发布前至少新增或保持以下端到端覆盖：

1. 首次连接模型并完成第一轮会话。
2. 创建项目、项目内新建会话、重命名、归档和安全删除。
3. 运行期间立即显示状态并完成流式回复。
4. 断线重连不重复执行。
5. 行内审批和 Inbox 审批都能恢复原运行。
6. Codex 或 TRAE 一键授权导入并查看原始数据。
7. 自动生成候选、接受候选、后续任务只读取 active 记忆。
8. 创建自动化、立即运行、查看运行会话和产物。

## 12. 产品指标

### 12.1 激活

- 完成模型连接率；
- 首次启动到首次发送时间；
- 首次启动到首次有效回复时间；
- 首日完成至少一个真实任务的用户比例。

### 12.2 工作闭环

- TaskRun 完成率；
- 发送后出现可见状态的 P95 时间；
- 中断、失败和断线后的恢复成功率；
- 工具调用后产物可发现率；
- 重复消息或重复工具执行次数，目标为零。

### 12.3 项目

- 创建项目后成功开始项目会话的比例；
- 项目会话错误归组次数；
- 项目删除导致文件或会话丢失次数，目标为零；
- 项目默认配置正确继承率。

### 12.4 记忆

- 自动治理成功率；
- 候选接受、编辑、合并和忽略比例；
- 单个活跃用户每周需要处理的候选数量；
- 已确认记忆在后续任务中的命中率；
- 用户纠正错误记忆的次数；
- 未经确认进入上下文的候选数量，目标为零。

### 12.5 信任

- 未经批准执行高风险操作次数，目标为零；
- 页面和后端状态不一致次数；
- 无来源候选数量，目标为零；
- 数据连接和同步状态误报次数；
- 应用重启后永久卡在 running 的对象数量，目标为零。

指标默认在本地聚合；任何上传遥测必须单独获得用户同意，且不得上传原始对话或文件内容。

以下条件同时满足，才能认为下一版本的产品主线完成：

1. 新用户连接模型后，可以从工作台完成一次真实任务。
2. 用户发送后立即看到运行状态，等待期间页面不空白。
3. 用户可以创建、配置、归档、恢复和安全删除项目。
4. 项目内新会话正确继承项目目录、智能体和模型。
5. 会话、Runs、Agents 和 Inbox 对同一运行显示一致状态。
6. 断线、重连和重复发送不会重复执行工具。
7. 用户可以在行内或 Inbox 处理阻塞决定并恢复原执行。
8. Codex 或 TRAE 可以一键授权、连接、导入并查看来源记录。
9. 导入后系统自动生成候选，无需用户先找到“生成候选”按钮。
10. 候选未经确认绝不进入后续任务上下文。
11. 用户能在 Memory 首页看懂 Smallink 当前如何理解自己。
12. 自动化使用与普通工作相同的运行、权限、审批和产物链。
13. 正式界面不展示未验证连接器、假状态或 Mock 完成数据。
14. README、产品 PRD、架构导读和专项 PRD 的当前状态与代码一致。

## 15. 后续方向

本版本完成后，再进入以下建设：

1. 项目级统一聚合和跨模块筛选；
2. 混合检索、记忆冲突和效果反馈；
3. 正式知识库；
4. 通用多智能体编排、预算和 Checkpoint；
5. 事件触发自动化；
6. Postgres + pgvector 迁移；
7. 多设备和远程 Worker；
8. 多人协作。

这些能力必须继续遵循本版本确立的产品底线：真实状态、来源可追溯、用户控制、本地模式不被破坏。
